## ✅ Step 4: Test the Flow

### User Side (`/my-wallet-p2p`)
1. Go to "Tạo lệnh rút" tab
2. Fill in form:
   - Amount: 100,000 VND
   - Bank: VCB
   - STK: 0123456789
   - Name: TEST USER
3. Click "Tạo lệnh rút"
4. Note the order code (WD-YYYYMMDD-XXXXX)

### Admin Side (`/admin/withdrawals-p2p`)
1. Filter by "Chờ duyệt" (PENDING)
2. See the withdrawal request you just created
3. Click "Duyệt lệnh" (Approve)
4. Click "Xác nhận đã chuyển" (Confirm Payment)
5. Fill in:
   - Trace ID: `TEST-123456`
   - Transfer Content: `PAY WD-YYYYMMDD-XXXXX`
   - Time: Now
6. Click "✅ Xác nhận đã chuyển"

### User Side (confirmation)
1. Go back to `/my-wallet-p2p` → "Lịch sử"
2. Status should be "Chờ bạn xác nhận"
3. Click "✅ Đã nhận tiền"
4. Status becomes "Hoàn thành"

### Testing Dispute
1. Create another withdrawal
2. Admin approves and confirms
3. User clicks "⚠️ Mở tranh chấp"
4. Type reason (e.g., "Chưa nhận được tiền")
5. Status becomes "Tranh chấp"

## 🔗 RPC Functions (Created in DB)

1. `generate_withdrawal_order_code()` - Auto-generates WD-YYYYMMDD-XXXXX
2. `create_withdrawal_request_p2p(...)` - Creates order, deducts balance
3. `admin_approve_withdrawal_p2p(...)` - Admin approves, status → WAITING_FOR_ADMIN_PAYMENT
4. `admin_confirm_payment_p2p(...)` - Admin confirms payment, status → AWAITING_USER_CONFIRMATION
5. `user_confirm_receipt_p2p(...)` - User confirms, status → COMPLETED
6. `user_open_dispute_p2p(...)` - User disputes, status → DISPUTED

## 🎯 Key Features

✅ **Order Code System**
- Format: WD-YYYYMMDD-XXXXX (unique per day)
- Auto-generated by system
- Used as transfer content reference

✅ **QR Code Integration**
- Admin scans QR with banking app
- Auto-fills: Amount, STK, Transfer Content
- Reduces manual entry errors to near-zero

✅ **Payment Proof**
- Bank Trace ID (from bank statement)
- Transfer timestamp
- Transfer content verification
- Optional image/PDF proof upload

✅ **Dispute Handling**
- User can open dispute if no payment
- 24-48h timeout recommended
- Complete audit trail
- Evidence from both admin + user

✅ **Status Workflow**
- PENDING (user created)
- WAITING_FOR_ADMIN_PAYMENT (admin approved)
- AWAITING_USER_CONFIRMATION (admin paid)
- COMPLETED (user confirmed)
- DISPUTED (if issues)

✅ **Immutable Bank Account**
- User cannot change STK after order creation
- Prevents fraud redirects
- Admin can verify STK matches in bank

## ⚠️ Important Notes

1. **Balance Deduction**: `balance_thuong` is deducted IMMEDIATELY when order is created (at RPC level), not when admin confirms. This prevents user from creating multiple orders with same balance.

2. **Order Code Format**: `WD-YYYYMMDD-XXXXX`
   - WD = Prefix (Withdrawal)
   - YYYYMMDD = Date (e.g., 20250130)
   - XXXXX = Random 6-digit number (0-999999)

3. **Transfer Content**: Must be exactly `PAY WD-20250130-000245` format
   - Admin should copy exact order code
   - User can verify in bank statement
   - Used for dispute resolution

4. **Trace ID**: Bank's transaction ID
   - Example: `20250130ABC123` or similar
   - Proof of actual transfer in bank system
   - Required for payment confirmation

5. **RLS (Row Level Security)**:
   - Users can only see their own withdrawals
   - Admins can see all withdrawals
   - Users can only dispute their own orders

## 🧪 Troubleshooting

### "User không tồn tại"
- Check user ID is valid in profiles table
- Ensure user is logged in

### "Số dư không đủ"
- Check balance_thuong field in profiles
- Ensure amount requested ≤ balance_thuong

### "Chỉ có thể duyệt từ trạng thái PENDING"
- Order is already approved or completed
- Check status in withdrawal_requests table

### "Không có quyền xác nhận"
- User trying to confirm wrong withdrawal
- Check withdrawal user_id matches auth user

### QR Code Not Showing
- Check `qrcode.react` is installed in package.json
- Verify QR component renders

### RPC Function Not Found
- Check database migration was executed
- Verify function syntax in Supabase SQL Editor
